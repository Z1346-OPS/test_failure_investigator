## 2. 本轮目标和范围

让首次使用者不用读完整手册，也能找到材料、完成一项人工核对、返回同一次调查并保存交接说明。

先完成 G2 缺图场景的完整路径；G1 QR、G3 打开设备失败先补齐材料来源、已有结果的下一步和交接出口。其他 G2 分支保持准确解释，不伪装为已有完整修复流程。

继续使用标准库、Tkinter 和当前单窗口。程序只读取用户选择的已有报告。用户在助手之外手动操作，助手不运行任何检查命令。

本轮不做：数据库、FastAPI、网络服务、DeepSeek/模型调用、网页跳转、聊天框、自动扫描目录、自动修复、跨运行恢复判定扩展、批量证据包或持久化历史中心。技术栈扩展另立任务。

## 3. 交互要求

### 3.1 先帮助找到材料

- 首屏保留“选择已有报告”，将材料帮助明确命名为“报告在哪里 / 我没有报告”。帮助在窗口内可读、可返回；不能只打开外部手册。
- 不要求用户把所有错误文件搬到一个固定文件夹。不自动扫描磁盘或猜测最新版。
- 按三类材料给出来源、识别方法和选择范围：
  - QR：摄像头项目 `analyze_label.py` 的 `--output` 指定文件，`label_baseline` v2；不是图片、expected 文本或批量评测 JSON。
  - 采集任务：用户当时 `--output-dir` 指定目录里的 `capture_task.json`，`camera_timed_capture` v1。
  - 采集复核：`review_capture.py` 输出到终端的 JSON，`capture_task_review` v1。它没有 `--output`，不能声称运行后自动存在 review.json。保存方式必须对照摄像头项目现有 walkthrough 核实，提供手动步骤时注明输出新文件、不覆盖旧文件。
- 路径来自用户的实际选择或当时的运行参数；开发者 D 盘路径不能显示成每个人的默认位置。
- 找不到材料时，允许记录“找不到 / 不确定”并获得交接指引；也可以查看明确标为合成练习的现有案例。尚未导入材料时，不显示已经诊断或复验的结论。
- 本次不修改读取器支持的三类 schema，不让用户导入 CSV、PNG、普通日志或整个目录。

### 3.2 当前操作卡

主区保留发现与关键限制；将“还不能确认”改成更直接的“这份报告还不能说明什么”，每项用短句解释其影响，不隐藏 ROI 错误、缺真值或不可比较的事实。

每次只突出一个动作，显示：

1. 现在做什么，以及与哪条发现有关。
2. 去哪里，具体做哪一到三步。
3. 做完看什么。
4. 回来后记录观察，还是选择哪种新报告。
5. 做不了、不确定或没有结果时如何保存交接并停止。

不要强迫每个动作产生文件；人工观察可以只有用户反馈。也不要把“我完成了操作”当成“问题已修好”。

G2 缺图最小路径：已有复核报告指出帧无法核实 → 提示用户找到该次任务目录、核对对应图片是否存在（只人工查看，不让用户伪造/替换图片）→ 记录观察或无法完成 → 若用户另行获得新的复核报告，选择“添加操作后的结果” → 核对同批次、同范围及口径 → 显示变化或比较限制 → 保存说明。

报告本身不足以确定目录时明确告知；不得从报告内路径自动打开或读取更多文件。图片存在也不能单凭反馈将复验改成通过。

### 3.3 避免误开新调查

- “换一份报告”改为次要操作“开始另一件问题”，就近说明将开始新调查。
- 当前调查主操作使用“添加操作后的结果”，就近说明保留原报告并核对变化。
- 保留草稿、未保存提示、取消和保存失败保护；仅换按钮文案不能改变这些语义。
- 用户反馈提供简短选择：已做完、问题仍在、暂时没再出现、做不了或不确定；根据当前卡显示适用选项，避免一次铺满按钮。反馈始终是未独立验证的用户声明。
- 新结果回来后，当前卡必须根据现有记录更新：已补充的材料不再反复索取；有新问题要显示；不可比较要解释缺什么、允许交接。不能只显示原始报告的旧下一步。
- 不放宽现有复验可比条件。用户声明同一问题不能覆盖不同对象或口径冲突。

### 3.4 指引和记录同源

采用一个轻量的版本化指引来源，可新增 `src/investigator/guides.py`，不引入工作流框架。记录指引 ID、版本、步骤 ID、适用条件、材料要求、动作、预期观察、停止条件和核实来源。

界面中的当前卡、详细帮助和导出读取同一份指引内容；不要在 ui.py、export.py 和手册里维护三套相互独立的动作文案。README 仅讲入口与流程。

会话记录建议过的步骤、用户反馈和关联的新结果；旧步骤记录不被当前卡覆盖。导出新增“建议过什么、用户声明做了什么、带回什么、仍缺什么”，仍使用预览与实际写入同一 payload、独占新建和现有敏感信息边界。

## 5. 风险、依赖与回退

- 新按钮使用户反馈变成复验结论 → 用无新报告的反馈用例核对五维状态 → 撤回对应状态转换，保留旧判定。
- 新结果已导入，卡片仍显示旧建议 → 用正常转异常、异常转正常及不可比较路径核对 → 回退卡片选择逻辑，不能清除旧证据来掩盖。
- 硬编码开发者路径、错误宣称报告自动落盘 → 对照入口和参数逐条审查 → 去掉未经核实步骤，提供交接出口。
- 界面、导出和帮助内容漂移 → 核对同一 guide ID/version/step ID 及操作内容 → 恢复为单一来源。
- 当前无首次提交，难以区分原型与新增内容 → 修改前摘要、备份及逐文件前后 diff → 仅恢复本轮文件，不覆盖用户并发改动。

依赖仅为现有 Python 3.12 环境、Tk 图形会话、现有合成样例和摄像头项目只读文档。没有 API、安装或 Linux 验证前置要求。人工体验必须由真实用户完成，执行者不可代填通过。

## 6. 验证与完成条件

执行前阅读测试脚本，确保只在本项目或临时输出目录产生测试产物。先运行现有基线，再在实现后运行：

```powershell
.\.venv\Scripts\python.exe -B -X utf8 -m unittest discover -s tests -t .
.\.venv\Scripts\python.exe -B -X utf8 tests\gui_smoke.py
```

必须覆盖：

- 没有报告时能找到材料帮助、合成练习或交接出口，不虚构已检查结果。
- G2 缺图 → 人工观察反馈 → 原复验状态不被升级 → 添加同对象新复核 → 当前卡和导出更新。
- 正常 → 新异常不能通过；异常 → 可比正常只支持范围内结论；不同运行仍保留比较限制。
- G1 无独立答案不能宣称正确，整图读出不能隐藏 ROI 错误；G3 后续完成不能证明根因或物理恢复。
- 新调查与补充结果语义不同，草稿不丢失、旧说明不串入；取消选择、坏文件、保存取消/失败保留原调查。
- 预览与实际文件一致，包含步骤历史与用户声明，仍不覆盖同名文件。
- 同版指引在帮助、卡片和导出中的内容一致；未知场景明确交接，不猜修复动作。

GUI 验证使用真实 Tk 控件；文件对话框或失败注入若为模拟必须单列，不能写为人工验证。环境缺少图形能力时报告未验证，不用单元测试代替。

人工体验安排：让用户先在不读完整手册、不展开技术详情的情况下，完成一个明确标注的合成 G2 案例；观察是否知道文件在哪里、此刻做什么、回来点哪个按钮、导出是否说清未知。记录实际帮助次数和具体卡点，不预填耗时/收益。不涉及摄像头采集。

实现与自动化检查完成只能称“等待人工体验”，不能称产品验收通过。人工体验无重大卡点后，再单独评估会话持久化的必要性；暂不增加后端服务。

## 7. 执行总结格式

Claude Code 完成后必须报告：

1. 做了什么：逐文件列改动目的，区分原有功能与新增功能。
2. 未做成什么：失败、阻塞、偏离计划及其影响；没有则明确写无，不省略此项。
3. 验证：实际命令、退出码、通过/失败/跳过数量，GUI 真实驱动与模拟部分，历史结果单列。
4. 未执行：人工体验、系统对话框人工点击、摄像头、安装、网络、Linux、提交推送等分别如实写明。
5. 审核材料：修改前后差异、指引核实来源、合成案例位置、界面入口、遗留限制。
6. 结论：实现完成待审核 / 部分完成并列阻塞；不得自动提交、推送、创建分支或继续扩展。
