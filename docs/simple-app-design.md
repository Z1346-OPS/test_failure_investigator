# 简化版程序设计：选报告、看解释、保存说明

日期：2026-10-17（Asia/Shanghai）。状态：交互与范围设计，尚未实现、未进行用户试用。

定位沿用 [product-direction.md](product-direction.md)。**首版程序的交互与功能取舍以本文为准**；[workflow-design.md](workflow-design.md)作为内部证据、关联和状态约束参考，不逐步照搬成界面。仍先试用指引，再根据实际困难实施本地程序；本轮不写代码、不选框架、不安装依赖。

## 1. 首版只解决这一件事

用户选择一份摄像头项目的已有报告，不必理解 JSON，就能知道“发生了什么、还不能确认什么、下一步能做什么”，并保存一份可交接的说明。需要时补充已有的新结果，核对变化。

基础无需 AI、账户或网络。程序只读源材料，不启动摄像头、不重新分析图片、不复算指标、不修改配置或修代码。复杂的证据规则留在内部；界面和技术详情共用同一记录。

| 保留在首版 | 暂不进入首版 |
| --- | --- |
| 选择已有报告、自动识别、解释三类场景 | 自动扫描目录、整仓导入、任意日志诊断 |
| 一项明确的下一步、补充结果、必要的前后比较 | 自动检查/修复、根因猜测列表、评分和置信度 |
| 折叠的技术详情、可选用户说明 | 必填调查表、多目标任务管理、复杂仪表盘 |
| 预览并保存一份 Markdown 说明 | 多文件证据包、批量导出、自动发送、云同步 |
| 本次会话内保留原结果和追加结果 | 历史中心、自动跨会话恢复、数据库管理界面 |
| 简单本地界面 | 聊天框、模型配置、Skill/插件入口、账户设置 |

## 2. 一个窗口，三种内容状态

没有侧边栏、步骤进度条或强制“下一页”。主区域随当前内容变化，不要求用户走完所有内部步骤。

### A. 尚未选择报告

标题“排查助手”，一句说明“选择已有报告，了解结果和下一步”，一个主按钮“选择报告”。下方两个次要入口：“支持哪些报告”“我还没有报告”。

选择后默认任务为“读懂这份报告”，直接显示结果；不先要求填目标、版本、设备编号、问题描述。时间、类型、版本等能读就读；没有就标未知，不补猜。

“我还没有报告”只展示三类问题对应的最小材料提示，允许返回或退出，不启动设备。已知位置来自用户选过的文件或经核实的说明，不能编造用户机器上的报告目录。

### B. 已有结果

下面是静态文字草图，不是可运行原型。示例仅表示一份单一读出、无真值的 QR 报告。

```text
排查助手                              换一份报告
QR 分析 · 本次先帮你读懂报告

目前发现
读出了一个二维码。

还不能确认
没有独立答案，尚未验证内容是否正确。

下一步
确认是否有独立的原始答案和已有比对结果。
没有也可以保存当前说明，交给技术人员继续处理。

[ 补充结果 ]   保存说明

▸ 查看技术详情        补充说明（可选）
```

每次最多一个强调的主按钮。主区用简短自然语言，文件标识、数量、错误码、原始字段和证据定位放在技术详情。**关键错误与未知不能藏进折叠区**：例如整图读出但 ROI 出错，主区同时说明，不能只挑较好结果。

“补充说明”展开一个可选文本框，只记录用户做过什么、主观是否改善，不要求填完整表。它始终标为用户反馈，不提升成已执行检查或复验通过。

### C. 补充结果后

保留原报告，在同一窗口增加“与之前相比”短说明，例如“新报告仍提示同一帧无法复核”，或“这份报告属于另一批次，不能证明之前的缺图问题恢复”。原结果可在技术详情中查看，不覆盖。

读取新报告时先核对对象、运行/分析标识、区域、版本和条件。能从记录确定的内容不再问用户；仍有关键歧义才显示**一个短问题**，如“这是刚才问题的后续结果，还是另一件事的报告？”用户可选“不确定”，程序保留不可比较状态。

默认仍解释记录，不自动宣布恢复。需要评价复验时显示具体评价项，如“核对之前缺失的图片能否复核”；可读性、内容正确性和设备可用性不能互相替代。用户可纠正评价项，但不能静默把目标降低。

## 3. 输入、解释与下一步

首次支持三类经过版本识别的结构化报告：采集任务 `camera_timed_capture` v1、采集复核 `capture_task_review` v1、QR 分析 `label_baseline` v2。JSON 内容可能保存在 `.json` 或 `.txt` 中，以结构和版本识别，不仅看扩展名。普通日志不属于自动诊断输入，必要时提示交给技术人员。

首次允许选一份主报告；补充时可同时选择相关任务/复核报告，逐份列出接受或拒绝结果。拒绝未知版本、损坏/超限文件或越界路径，不丢掉已经有效读取的报告。源文件里的其他路径不自动跟随；不扫描整个目录。读取、关联、预算和来源规则继承详细流程第 4 节。

| 场景 | 主界面解释重点 | 下一步优先建议 |
| --- | --- | --- |
| QR | 是否读出、是否有歧义/错误、是否有独立答案；区域结果分开 | 核对已有答案来源/已有比对结果；缺少就保留未验证并交接 |
| 缺图或指标差异 | 哪个对象无法核对或出现差异；任务完成与复核结果分开 | 核对对应批次、文件位置和已有复核材料；不归因为磁盘或硬件故障 |
| 打开失败 | 该次打开未成功；后续记录是否支持目标设备可用 | 对照请求设备与用户意图，补充已经手动产生的后续采集/复核结果 |

下一步沿用已核实指引，最多突出一项：标题加简短操作说明，并说明需要带回什么。未核实的操作不生成命令。没有可继续的已知步骤时，明确建议保存说明交接，不凑原因或反复要求重试。

多项问题同时存在时，优先指出阻止判断的冲突/缺材料，再指出执行错误、业务问题，最后列出局部正常结果。这个顺序仅控制展示，不改变原始状态；其他关键问题仍在主区简要列出，不只剩一个绿色总状态。

## 4. 保存与退出

“保存说明”先在窗口内预览，再让用户选择新的 `.md` 文件位置。默认只生成**一份可阅读的文件**，包含：短结论、下一步、尚未确认、用户补充、前后变化和折叠区对应的技术详情；内容来自同一份调查记录。

技术部分保留来源文件标识、格式/版本、已有运行标识、证据定位/摘要、原始状态、比较范围和缺口；默认不带本机绝对路径、原图、QR 原始载荷或整段日志。仅输出已审查字段，不把未知文本直接拼进文件；含敏感信息的内容须删改并标注损失，不能承诺自动脱敏完备。

这是一份说明，**不是完整原始证据包，也不是可恢复会话的项目文件**。明确列出“未附原始文件，技术人员可能仍需索取”，不能宣称接手者已获得全部证据。完整包和结构化恢复留待试用确有需求再设计。

保存成功后显示文件位置。目标已存在时要求换新名称，不覆盖；取消或写入失败就留在原界面，不显示成功、不丢本次内容。保存只是本地保存，不发送，也不意味着问题解决。

普通查看后退出不反复打断用户；若有尚未保存的用户说明或新增比较记录，换报告/关闭时才提示“保存说明 / 放弃本次内容 / 返回”。首版不自动跨会话恢复；下次可重新选择原报告及后续报告。未保存的新增内容可能丢失，必须在退出提示中讲清楚。

## 5. 看起来干净，也确实容易用

- 浅色中性背景、单一强调色、清楚的标题与留白；不用装饰图表、大色块或密集卡片。颜色之外始终有文字表达错误/未知，不能靠红绿区分。
- 默认字号可读，支持系统缩放和键盘操作，焦点清晰。小窗口按纵向排布，不要求横向滚动才能看结论或按钮。
- 不展示内部状态机、证据编号输入框或技术步骤编号；证据编号仍保留在技术详情和保存说明中。
- 读取时显示“正在读取报告”，绝不写“正在检测相机”。读取失败说明哪个文件和下一步，不弹出无上下文的堆栈。
- 异常提示靠近相关材料，不用一串弹窗；不接受/缺材料/无法比较都有继续查看已有结果或保存说明的出口。

## 6. 与详细流程的对应与验收

| 原详细流程 | 简化版如何处理 |
| --- | --- |
| P0 先确认目标，再导入 | 先导入，默认解释报告；比较或目标歧义影响判断时再确认 |
| P1–P6 分步调查 | 收敛为同一窗口里的选择、结果、补充三种状态，内部核对条件保留 |
| 多目标、暂停/结束/继续 | 首版仅当前问题；内部保留来源和修订，不暴露任务管理按钮 |
| 多文件 summary/record/manifest 导出 | 首版一份 Markdown 说明，明确未附原始证据；完整证据包暂缓 |
| 五维记录和复杂状态 | 保留内部事实边界，主区只呈现对当前判断重要的信息 |

以下是设计验收目标，尚未验证：

1. 正常首用只需选择受支持报告即可看到解释，不必填写任何技术字段；读取耗时在原型阶段实测，不预先承诺秒数。
2. 用户能复述“发现什么、还不能确认什么、下一步做什么”；打不开技术详情也能完成这一任务。
3. QR 单一读出不显示“内容正确”，缺图不显示“磁盘故障”，用户说恢复不直接显示复验通过；关键错误不被正常项覆盖。
4. 新旧记录可比较时显示范围和变化；不可比较时说明原因，不覆盖旧失败。
5. 不支持的文件和读取失败不破坏已查看结果；没有报告也能获得材料提示。
6. 保存说明不要求另填表；技术接手者能定位来源与缺口，且知道未附哪些原始材料。
7. 取消保存、重名、写入失败、关闭未保存内容均不会被误报为保存成功。
8. 先以文字草图和已有材料试用，沿用[首轮试用计划](first-guide-and-trial-plan.md)的误判与自助完成门槛；简化交互不能降低证据要求。需要反复解释界面或填写表格时，先减内容再加功能。

本轮只新增简化设计，并在方向及详细流程文档增加优先级入口；不改历史报告和已有指引。下一步仍是用这三个内容状态走查真实材料、记录卡点，尚未授权自动进入编码或运行摄像头。
