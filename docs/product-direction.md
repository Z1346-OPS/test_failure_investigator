# 产品方向：排查指引与证据助手

日期：2026-10-17（Asia/Shanghai）。状态：方向已确定，文档初稿落盘；产品与试用尚未实现/开展。

## 定位与边界

为 `D:\Projects\Python\camera-quality-diagnostics` 提供独立助手，首批用户是使用该摄像头项目的 Windows 用户。帮助用户理解问题、完成下一项人工检查、核对恢复结果，并整理可供技术人员接手的记录。基础能力无需 AI，不要求普通用户理解 pytest 或建立模型评测包。

普通指引显示结论边界、下一步和需要带回的结果；技术详情展示原始字段、来源与缺口。两者共用一份调查记录，不产生两套事实。保留现有项目目录名，不迁移摄像头工程。

首版只读取用户选定的已有记录，不启动摄像头、不执行检查、不改配置、不修代码、不自动复跑。用户在外部手动操作，再导入新结果。助手可新建自己的调查记录和交接文件，不能覆盖输入、原图或历史报告。阶段一用文档模板手动整理，自动导入和导出属于后续实现。

不做通用相机故障诊断、工业合格判定、任意仓库排错或自动修复。不默认上传记录、原图或 QR 载荷，不默认引入重型框架。

## 一份记录、五个独立维度

| 维度 | 必须保留 | 不可替代的判断 |
| --- | --- | --- |
| 执行情况 | 谁在何时使用什么工具/版本/参数；来源、阶段、原始状态与退出码或未知 | 进程结束不等于业务目标成功；导入不等于本轮执行 |
| 业务问题 | 单一读出、歧义、缺图、指标差异等观察及证据引用 | 业务异常不自动等于程序崩溃或硬件损坏 |
| 用户反馈 | 原话、时间、操作与主观感受 | “看起来好了”不等于复验通过 |
| 复验结果 | 目标、前后记录关联、可比条件、通过/未通过/不可比较/待结果 | 新记录不覆盖旧失败；恢复不证明原因 |
| 根因判断 | 未知或候选；支持、反证、缺口、适用范围 | 有引用不等于证实；不输出无依据百分比 |

记录还包含调查 ID、指引版本/步骤 ID、证据索引、下一步和停止/交接原因。原始事实与分析分开，未知不补猜。阶段一人工按模板填写；后续程序负责状态、证据、权限、预算和报告一致性，可选模型负责解释与调查步骤选择，无权改写事实或扩大权限。

必须守住：QR 单一读出不是内容正确，缺少独立答案保持 `not_provided`；缺图不能直接归因为磁盘写入失败；指标一致不等于相机合格；某次恢复不覆盖原失败。

## 建设顺序与进入条件

| 阶段 | 交付与验收 | 何时继续 |
| --- | --- | --- |
| 1. 独立排查指引 | 经来源核实的场景卡、共用记录模板、交接清单；读者能解释现象、找出下一项动作、保留未知并交接 | 按[首轮计划](first-guide-and-trial-plan.md)试用；先修订误导与卡点 |
| 2. 本地交互式向导 | 无 AI 也能选择场景、导入已有结果、提示下一步并新建导出；与指引同源 | 实际困难来自文件定位、步骤遗漏或记录整理，且交互对照减少负担；不以向导遮掩内容错误 |
| 3. 可选 Skill | 共享同版指引、步骤和记录，按需加载；宿主协助解释与选择步骤 | 宿主中存在重复需求；不用 Skill 仍可完成基础流程；权限不因 Skill 扩大 |
| 4. 可选 API/动态取证 | 另行设计和授权；受限只读补证据、预算与终止可验证 | 对照证明优于无 AI/固定材料解释，计入准备、重试、核验和维护成本；无增益则不扩展 |

拟采用显式流程：选择问题 → 核对已有证据 → 给出人工下一步 → 等待新记录 → 核对复验 → 结束或交接。缺材料保持等待/证据不足；冲突保留并交接；用户可随时停止。助手自身无“正在运行相机/修复”状态。这是设计选择，尚无程序实现。

逐步输入/输出、三组场景分支、状态转换、复验与交接条件见 [具体流程设计](workflow-design.md)。该设计用于先做文档走查；交互式向导仍须满足上表的试用条件后再实施。

当前程序交互与首版范围以 [简化版程序设计](simple-app-design.md) 为准：单窗口，先选报告，再看解释，按需补充结果或保存一份说明。详细流程保留为内部约束，不要求用户填写调查表或逐步走完；多文件证据包和历史中心暂缓。

## 本轮交付与验收

新增本文与[首轮指引及试用计划](first-guide-and-trial-plan.md)，同步根目录规则。优先场景：QR 结果解释、缺图/指标不一致、设备打开失败后的恢复核对；明确区分实机记录和合成反例。本轮核实已有材料，未开展用户试用或摄像头复测。

文档验收：每个场景有适用条件、来源、下一步、应带回证据及停止条件；五个维度不混淆；普通说明与技术字段一致；新旧方向关系清楚；历史文件保持原字节。当前没有可执行入口或 build/test/lint/type-check 配置，不以文档核验代替产品运行验证。

## 历史与参考依据

[原 pytest 设计](design-v0.md)、[工程辅助调研](research-agent-project-assist-2026-10-16.md)、[个人策略调研](research-agent-personal-strategy-2026-10-16.md)保留为历史。新方向替代其中的当前定位与建设顺序；保留状态分离、证据可追溯、权限/预算和评测隔离原则。原 reported_samples 重建不是当前前置任务，历史设计含评测答案，不可作为未来被测模型输入。

最新完整调研报告尚未保存。本轮只对用户提供的三项第三方要点核对官方文档（2026-10-16），不冒充恢复原报告，也不视为本机运行验证：

- [Troubleshoot Collecting Data](https://troubleshoot.sh/docs/collect/)将收集与分析分阶段，分析使用收集产物。本项目借鉴事实与分析分离，不引入其采集器或执行能力。
- [pytest TestReport](https://docs.pytest.org/en/stable/reference/reference.html#testreport)分别记录 `when`（setup/call/teardown）与 `outcome`（passed/failed/skipped），收集另有 CollectReport。本项目借鉴维度分离，不把摄像头状态硬套为 pytest 结果。
- [Agent Skills 规范](https://agentskills.io/specification#progressive-disclosure)描述元数据、激活后指令、按需资源的分层加载。它是内容组织参照，不证明特定宿主兼容、权限隔离或成本降低。

显式状态机与暂不引入重型框架是本项目的范围决策，不是已验证的性能优势。第三方维护状态、Windows 兼容、许可证和安装行为须在真正选用组件时另行核查；本轮没有安装组件。
