## 2. 修复后行为

- 复验先检查新结果：新结果未复核、整体未完成或状态未知时判“证据不足”；新结果登记了问题判
  “未通过”，并在界面和导出中列出“新出现”的问题；原记录干净不能跳过新结果的检查。
- 同 `run_id` 但 `comparison_basis` 不同判“不可比较”；校验提示与测量口径缺失/不同不阻止暴露
  新问题，但阻止“通过”。
- 新调查使用新的调查 ID、创建时间，清空上一调查的说明、补充结果与临时界面状态；取消选择或
  读取失败保留原调查。
- “保存说明”先显示完整预览（可滚动），预览与写入复用同一份内容；保存区分成功、取消、失败。
- 关闭窗口、切换报告时，只有保存成功或用户明确放弃才继续；取消预览、取消文件对话框、写入
  失败都留在原界面并保留未保存状态。补充结果前对未记录草稿单独询问。
- 导出简明结论在存在补充结果时写明复验结果与新出现的问题。

## 4. GUI 实际验证与替代实现

真实窗口、真实控件与按钮回调验证：

- 启动、选报告、三块内容区、技术详情折叠、添加说明、补充结果。
- 正常→异常判“未通过”，界面出现“新出现”的问题，导出不写“范围内通过”。
- 新调查不带入旧说明；未记录草稿在展开技术详情、收起再展开后仍保留。
- 导出预览内容与保存文件一致，预览期间未被标记为已保存。
- 同名文件不覆盖、保存取消、关闭时保存取消/失败/成功、切换报告时保存取消/失败/成功。
- 取消选文件、读取损坏 JSON 不破坏原调查。

- 系统文件选择/保存对话框由固定路径替代；“拒绝访问”写入失败通过注入 `PermissionError` 模拟，

- 未保存提示、导出预览、保存错误提示等程序自有对话框由脚本真实点击按钮驱动。
