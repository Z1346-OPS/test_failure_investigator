# 排查助手（本地原型）

为 `D:\Projects\Python\camera-quality-diagnostics` 的用户提供一个单窗口的
**排查指引与证据助手**：选择已有报告 → 看懂结果和下一步 → 按需补充结果或保存一份说明。

基础能力**不需要 AI、账户或网络**。程序只读用户选择的已有文件，不启动摄像头、
不重新分析图片、不复算指标、不修改任何源材料。

交互与范围以 [docs/simple-app-design.md](docs/simple-app-design.md) 为准；
[docs/workflow-design.md](docs/workflow-design.md) 只作为内部证据与状态约束。

## 运行

需要 Python 3.12（本机实测 3.12.10）与 Tkinter；**没有第三方依赖**。

```powershell
# 1. 建立本项目的独立环境（不复制摄像头项目的 .venv，也不安装任何第三方包）
python -m venv .venv

# 2. 启动界面（在项目根目录）
.\.venv\Scripts\python.exe -X utf8 src\run_investigator.py
```

窗口打开后：点“选择已有报告”，选一份受支持的 JSON/TXT；界面直接给出
“目前发现 / 这份报告还不能说明什么 / 现在做什么”，不需要先填目标、版本或设备编号。

## 支持的报告

按内容、`report_type` 和 `schema_version` 识别，不只看扩展名（`.json` 与 `.txt` 都可以）：

| 报告 | report_type | schema_version | 场景 |
| --- | --- | --- | --- |
| QR 分析 | `label_baseline` | 2 | G1：读出、歧义、冲突、错误与内容正确性 |
| 采集复核 | `capture_task_review` | 1 | G2：缺图、指标差异、未完成复核 |
| 定时采集任务 | `camera_timed_capture` | 1 | G3：设备打开失败与后续恢复记录 |

导入只接受普通本地文件。读取器从路径根目录逐级检查；所选文件或任一上级目录是符号链接或 Windows 目录联接时，导入会被拒绝。读取时还会核对文件身份和大小上限。

未知版本、损坏 JSON、重复键、缺必要字段、越界路径或超限文件会被**明确拒绝**，
并且不会影响已经读到的其他结果。

## 三块内容与三个操作

- 主区域固定三块：**目前发现 / 这份报告还不能说明什么 / 现在做什么**；关键错误与未知不会
  藏进折叠区，技术详情才是默认折叠的部分。
- 主要操作：**选择已有报告**、**添加操作后的结果**、**保存说明**。
- 技术详情默认折叠；用户补充说明可选，且始终标为“用户声明，未独立验证”，不会变成复验通过。
- 步骤反馈（已做完、问题仍在、暂时没再出现、做不了或不确定）绑定到具体调查、
  主报告或“补充记录 N”及指引版本：做了的不再重复索取，“做不了或不确定”转入交接，
  后续补充记录不会继承前一份记录的反馈。
- 支持键盘操作（`Ctrl+O` 选报告、`Ctrl+S` 保存说明）与系统缩放。

“选择已有报告”开始一份**新调查**：新的调查编号和时间，不会带入上一份调查的说明、补充结果
或步骤反馈。“添加操作后的结果”继续当前调查；新结果存在缺图、指标差异等异常时判“未通过”，
不会被原报告的正常结论掩盖。是否可比仍按对象标识与比较口径判断，用户声明不能强行覆盖。

已输入但还没点“记录说明”的文字会暂存；关闭、切换报告或补充结果前会先询问，
不会静默丢弃，也不会混进用户反馈。

## 不会做的事

不启动摄像头、不运行摄像头项目的入口或测试、不修改摄像头项目的任何文件、
不重新解码图片、不复算指标、不执行输入里的命令、不跟随报告内的路径或链接、
不调用模型 API、不联网上传材料、不安装依赖。

判断边界（详见 [docs/product-direction.md](docs/product-direction.md)）：

- QR 单一读出**不是**内容正确；没有独立答案就保持未验证。
- 缺图/无法核实**不能**直接归因为磁盘写入失败；指标差异**不能**直接归因为硬件损坏。
- 用户说恢复**不等于**复验通过；后续成功**不等于**根因确认。
- 不同批次（不同 `run_id` / 不同图片）**不能**证明旧问题已恢复。

采集复核使用 `review_id` 标识执行，使用 `reviewed_at_utc` 判断先后。重新排版的同一次复核仍属于已有证据。历史报告可导入；缺少执行编号或 UTC 时间时，不能证明后续复验通过。批次问题要求原声明帧逐一覆盖，旧报告提前停止且未保存帧号时保留证据缺口。QR 两次都提供答案时，助手按答案摘要核对是否使用同一份答案。主报告未提供答案、同图补充报告首次提供答案时，“仍缺什么”分别标注主报告当时的限制和补充记录本次的内容核验结果。不同图片各自保留本次结果。

## 保存的说明

“保存说明”先在窗口内显示**完整预览**（可滚动），确认后选择位置，再独占新建一个 `.md`
文件；预览与实际文件复用同一份生成结果。内容包括：简明结论、下一步、这份报告还不能说明
什么、建议过什么、用户声明做了什么、带回了什么、仍缺什么、前后结果与比较限制、技术详情
与证据定位。

预览或保存被取消、写入失败时，留在当前界面，未保存状态不变，不显示成功。
关闭窗口或切换报告时若还有未保存内容，必须先保存成功或明确选择放弃才会继续。

默认**不导出**本机绝对路径、原图、二维码原始载荷或整段日志，并明确声明
“未附原始文件”——它是一份说明，不是完整原始证据包。目标文件已存在时不覆盖。
用户声明做了什么、建议过什么以及每条步骤反馈都写明所属的主报告或补充记录，
与界面当前卡一致，不会把某份记录上的反馈算到另一份上。

## 测试与冒烟

```powershell
# 单元测试（标准库 unittest，无需 pytest）
.\.venv\Scripts\python.exe -B -X utf8 -m unittest discover -s tests -t .

# 真实图形界面冒烟：启动窗口 → 选报告 → 看解释 → 补充结果 → 预览并保存说明
.\.venv\Scripts\python.exe -B -X utf8 tests\gui_smoke.py
```

冒烟脚本会创建真实 Tk 窗口并驱动真实控件回调，同时把窗口截图写到指定目录
（默认临时目录）。它需要可用的图形会话。系统文件选择/保存对话框用固定路径替代；
未保存提示、导出预览、步骤反馈按钮（已做完 / 问题仍在 / 做不了或不确定）等由脚本
真实点击按钮驱动。写入失败是通过注入 `PermissionError` 模拟的，未修改系统权限。

测试材料全部是 `tests/synthetic.py` 生成的**合成报告**，不含实拍图片、真实二维码载荷
或私人报告。

## 当前状态

### 查看采集问题

导入有已登记问题的采集复核报告后，在“当前调查”下查看判断依据、待补检查和交接备注。多个问题按未解决优先排列，点击某行切换问题。展开状态历史可逐条查看来源文件与报告 SHA-256 前 16 位；帧级关闭记录还显示原数组位置和实际帧号。也可复制当前交接摘要。重复导入不增加一次关闭。

### 用 Python 查询采集问题

从仓库根目录运行 `.\.venv\Scripts\python.exe -B -X utf8 src/query_issue.py P01 主报告.json 补充报告.json` 即可查看该问题的关闭判断、证据位置和缺失检查。
未知问题编号时，用 `src/query_issue.py --list 主报告.json 补充报告.json` 查看编号和状态，再用相同报告顺序查询所选问题。
已有调查对象可调用 `session.get_issue_details(session.investigation_id, "P01")`。
返回值是可 JSON 序列化的 v1 快照，包含当前状态、逐次历史、证据定位、缺失项及下一步。
补充报告的核实帧集合、执行编号和 UTC 时间也写入新导出的交接说明。
完整示例和错误约定见[采集问题详情查询](docs/capture-issue-query.md)。

### 用 Python 核对单份 QR 报告

从助手仓库运行 `.\.venv\Scripts\python.exe -B -X utf8 src/query_qr.py 分析报告.json --region full_image`。把 `full_image` 换为 `roi` 可查询该报告的人工选区。命令只读报告，按报告 SHA-256 和 `evidence_paths` 定位依据，输出所选区域的判断和待补检查。

`correct` 和 `incorrect` 分别表示报告记录本次区域读码与独立答案逐字节一致或不一致。`unverified` 表示证据不足，`not_checked` 表示报告没有该区域。`missing_evidence` 针对本次内容判断。业务结果返回 0，参数、文件或报告类型错误返回 2。

追加 `--primary 原报告.json` 可将位置参数指定的补充报告与主报告比较。例如 `src/query_qr.py 补充报告.json --region roi --primary 原报告.json`。`primary_region` 和 `followup_region` 各自说明所选区域的结果，`report_comparison` 使用调查会话核对两份报告的全部区域，给出可比性、复验判断和证据位置。`original_issue_status` 为 `closed_in_scope`（原登记问题在本次范围内可关闭）、`unresolved`（原登记问题仍未解决）或 `no_registered_issue`（原报告没有登记问题）。关闭已登记的 QR 问题需要独立的分析编号，以及晚于原问题且可确认时区的分析时间。
